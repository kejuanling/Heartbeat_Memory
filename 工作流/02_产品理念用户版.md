# 02 产品理念（用户版，非必读，偶尔翻）

记一些我需要记住的功能设计决策。不是技术实现，是"为什么这么做"。

## 日记系统

**写入两条路**：
- AI 在回复末尾写 `[DIARY]...[/DIARY]` 标签块
- AI 调 write_diary 工具写

**落盘**：
- 日记正文存 `data/diary.json`（单 JSON 文件，id 按创建顺序自增，不回收）
- 时间线追加一条 `kind:diary` 的隐藏 assistant 消息，content 是 `[DIARY]...日记全文...[/DIARY]`
- 普通 assistant 消息落原始完整文本（含 [DIARY] 块），不剥任何东西——后端时间线是流水账

**在 AI 上下文里**：
- kind:diary 消息作为一条 assistant 消息发给 AI，AI 能读到完整日记
- kind:diary 消息不被压缩（isDiaryEvent 保护），时间线文件里永久原文存在，不被概括
- 跨窗口注入有篇数限制（最近 N 篇），时间线上的日记只要不删就一直存在
- 窗口滑出的老日记不每次都发，靠日记检索工具/跨窗口注入按需调取

**在前端**：
- 聊天界面显示时剥掉 [DIARY] 块，用户看不到标签和日记正文
- history API 下发原始 content，剥标签在前端 stripInnerTags 做
- 点编辑时编辑框填原始 content（含标签），方便检查核对
- kind:diary 消息 history API 过滤掉，前端不显示

**hidden=true 的日记**：
- 不注入上下文
- 不参与跨窗口注入
- 日记检索工具也检索不到
- 和删除等效，只是用户可以在日记页恢复显示


## 相关记忆注入（Possibly Relevant Memories）

**为什么做这个功能**：聊天时 AI 应该记得"最近发生过的具体的事"，聊到相关话题能接上话。之前做过一版"按意思相近捞记忆"，结果老把不相关的也捞进来，感觉不聪明，就下线了。现在重做，改成**靠关键词命中 + 语义补一点**，少而准。

**记忆分三类**：
- fact：关于人的稳定特质（她学什么专业、喜欢什么口味）
- rule：规则、边界、承诺（回复不要用 emoji、以后不要提某件事）
- event：具体发生过的一件事 / 做出来的东西（"她做了一个网页，域名是 xx"、"上个月我们一起去看了海"）——之后聊天可能还会引用

**每条记忆都带**：
- 关键词（1-6 个）：这条记忆的"门牌号"，聊天里出现这些词（或她的口语说法）就能把它捞出来。短记忆一个词就够，长的可以多个，最多六个。关键词不光是字面词——先选原话里的代表词保底，再补一两个她可能会随口说的说法（比如记忆是"她会速画速写"，除了"速写"还补"画画"，她哪天说"今天想画画"也能捞到这条）；原词够用就不强行补，别泛化成"艺术""创作"这种太宽的
- 氛围（可选）：这条记忆给 AI 的感觉（温暖、紧张、雨夜的潮湿感、海盐味）——用来判断"语境搭不搭"。没有明显感觉就不打
- 来源：这条记忆是从哪个对话里来的

**注入规则**：
- 只捞 event（一件事）。fact 和 rule 是"对人"的，开头两段固定注入就够了；event 是"对事"的，按当前话题浮动补充
- 打分 = 关键词命中×0.5 + 语义相关×0.15：关键词字面撞上了分高，意思相近的靠语义补一点
- 每轮只注入分最高的那条，最多一条
- 分太低（低于 0.3）不注入——宁缺毋滥
- 这件事本来就发生在当前这个对话里的，不重复注入（AI 刚才已经看到了）
- 氛围的作用是拦截：字面撞了关键词但语境完全不搭的，不捞

**event 会过时，所以有衰减**：
- 每次被注入，它的价值分涨一点
- 很久没被聊到，价值分慢慢降
- 降得太低（20% 以下）就移出主池，进待审，等处理
- 老记忆重跑整理时顺手更新价值分

**记忆入库时**：AI 要分清什么是一次性琐事（吃了什么、寒暄——不记），什么是值得记住的具体事（做了个网页、一次重要的经历——记成 event）。"气氛"不是用户自己说的，是 AI 感受到的氛围。

**管理台**：
- 每条记忆卡片能看到它的关键词和氛围
- 有个"相关记忆注入"配置区：权重、门槛、条数、衰减快慢，全部手动可调
- 有个"注入预览"：显示最近几轮本应注入哪条、分多少——上线前先用它观察准不准

**上线节奏**：存量老记忆全部重跑补好关键词、氛围、分类之前，不开启注入；等重跑完、预览观察准确了，再正式开。
## 记忆链路：谁在干活（大白话版）

一条记忆从产生到用起来，走一圈六个环节：

1. **蒸馏（捡）**：AI 每天看完对话原文和日记，挑出值得长期记住的原子记忆——分类（fact/rule/event）、打关键词、可选的氛围、标明来源。它只管捡，不打价值分。

2. **门卫（打分，不拍板）**：给每条候选打两个分——价值分（这条值不值得留，0-1）和时效分（这条会不会过时），各带一句理由。它不决定留不留：打低分也只是"交人工"，从不自动拒绝或合并。

3. **重跑（回锅）**：把池子里已经存着的旧记忆每隔一段重新过一遍——重新分类、补关键词、补氛围、顺手更新价值分。补完的标签再过一次门卫打分。所以门卫用两回：蒸馏出新的走一遍、重跑翻旧的再走一遍。

4. **两块总结（造人设底色）**：池子里的 fact 和 rule 分别被汇总成两块常驻文本——"规矩"（rule：边界、承诺、交互约定）和"理解"（fact：她的稳定特质）。每次对话开头都带着，AI 长期记得"她是什么样的人、有什么规矩"。

5. **相关注入（临场捞事）**：只捞 event。聊天聊到相关话题时，按混合分临时捞一条最相关的具体事补进上下文。纯算法，不调模型，每轮最多一条。

6. **记忆检索（AI 主动查）**：AI 拿不准时主动查记忆池（memory_search 工具）。它也走混合分，但类不限制（fact/rule/event 都能查）、最多返回 5 条。AI 用完整一句话问（"她上次说想学画画那件事"）比丢两三个关键词更容易命中——短词只做字面匹配，一句话会带意思相近的匹配。

**为什么分两拨**：fact/rule 是"对人"的稳定底色，固定常驻就够了；event 是"对事"的，平时不占上下文，聊到相关话题才临时浮现。所以只有 event 走"临场捞"这一套。

**节奏**：存量老记忆全部重跑补好标签之前，不开启注入；重跑完、预览观察准确了，再正式开。

## 日记在时间线里的位置

- kind:diary 消息放在状态机压缩摘要**前面**，不是落在压缩块覆盖范围内
- 原因不是防被摘要吞掉（isDiaryEvent 本来就保护），是为了前缀缓存命中——日记这段固定内容不变，放在压缩摘要前面，网关增量缓存命中率更高
- 补写老日记时，如果该日记原文落在 state 块覆盖范围内，kind:diary 消息要插到 state 块之前，不要插在范围内
