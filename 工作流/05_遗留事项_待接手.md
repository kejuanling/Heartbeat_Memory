2. **[待拍板] /v1/timeline/sync 旧分支语义覆盖** —— 触发：前端退化路径发整份 body.messages（ops 缺失或含无 id 消息），请求生成后服务器新写入的消息（他端消息/唤醒事件）不在客户端列表 → buildTimeline 全量重建物理删除。影响：多设备场景丢他端新消息（非并发竞态，客户端真源语义使然）。建议修法：旧分支改按 id 补齐+清尾（复用 appendRequestMessages 语义），或前端确认全走 diff 后下线旧分支。
3. **[待拍板] 会话删除幽灵复活** —— 触发：DELETE /v1/sessions/:id 时恰有生成中回复收尾 → appendMessages 对已不存在的文件 load 返回 [] → 写出只含 system+新回复的残骸文件，已删会话复活。影响：低频脏数据（写守卫不拦：文件不存在时无指纹可校验）。建议修法：删除时留墓碑集合，append 前校验拒绝；与 0918 看板 D 节「会话删除遗留孤儿」同族，可合并处理。
4. **[已确认·不修] 守卫已知 fail-open 边界**：size+mtimeMs 同毫秒碰撞漏报（概率极低，后果=回到无守卫现状）；corrupt 空数组被 sync 旧分支重建绕过（客户端真源既有语义）；守卫拒写后原语返回值不向上传播（靠 [timeline] 拒绝写入 error 日志可观测）。
