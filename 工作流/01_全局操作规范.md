## 失败经验（行为层，非技术命令）
> 本节记录**因判断/流程失误导致的高阶行为教训**，不记录具体命令坑（命令坑统一去 `02`）。

- **别信任静默成功**：脚本/服务重启要捕获退出码并确认，别只看“执行了”。
- **覆盖前先真备份**；别用 `-f`/`-y` 假备份，也别覆盖后才发现没留原版。
- **改完语法检查再 reload**：配置改了但不 reload/重启，等于没改。
- **别依赖“上一轮的缓存/旧副本”**：真值以远端/最新为准；工具结果不一定跨轮保留，要查就重查。
- **“加一个“往往是想多了，先问用户要不要单独的“通用/最小”工具**：需求方常只想要一个**最小的、单一职责**的工具，不要自作主张加前缀、多个专用工具或耦合逻辑。改工具前先用选择题确认。
- **系统级目录与文档路径不一致时以 systemd/实际为准**：改服务前先 `systemctl cat <服务>` 拿真实 `WorkingDirectory`+`ExecStart`，别按文档路径找文件。
- **注入上下文先过目**：任何会直接注入 AI 上下文的内容（提醒/备忘/系统提示/记忆/特殊事件等），实施前必须把**注入位置和渲染后的完整实际内容**拿给用户确认，问清是否要改、怎么改，确认后才推送上线——防止上线后返工。
- **子代理的审查结论必须回读原文才算数（2026-09-21 代码审查实证）**：并行派 N 个子代理分模块审查时，返回值里一定混有**误报**。本次 5 份报告中被抽验推翻的比例高达 4/5（把"后端会按 id 恢复脱敏密钥"说成会清空密钥、把已 `escapeHtml` 的函数说成未转义、把"当前配置不可利用"的设计缺陷说成现网漏洞）。结论不回读原文就写进交付物＝用幻觉污染用户的决策依据。派工时必须写明"每个结论要给出可复核的行号"，回收时必须自己 Read 一遍关键判定点再落笔。
- **多代理审查要预留重跑能力（2026-09-21）**：子代理会因模型 429 频率限制整体失败（本次 `Explore-5` 失败导致 `lib/wake-scheduler.js` 741 行未被完整通读）。分工时应①按模块边界切、每块控制在单个子代理 10 分钟内可完成；②失败后由主代理用定向 grep 兜底补上，并在交付物里**显式声明审查缺口**，不要假装全覆盖。
- **设缓存/性能阈值前先量线上真实数据分布（2026-09-22 实证）**：修「readJson 缓存驻留大对象」时我按直觉拟了「单文件 >1MB 不进缓存」，量完线上文件才发现方向反了——`context_replacements.json` 有 **18.7MB** 且是**每请求必读的热点**，按单文件阈值会把它踢出缓存、导致每轮重解析 18.7MB JSON（性能灾难）；真正该收敛的是「时间线多而碎」的累积。改用「48MB 总字节预算 + LRU」才对。**结论：设阈值前先 `ls -lS` 量真实文件大小分布，按"热/冷 × 大/碎"选「单文件阈值」还是「总预算」**——别拿直觉当依据。
- **别人（含审查报告）给的"建议改法"只是方向，落到具体代码约束前必须验证一遍（2026-09-22 实证）**：审查报告建议日记同秒重试的后缀由 `-1` 改成 `_1`，但全系统 5 处扫描/校验正则都要求 `_\d{4,6}`（**4–6 位**），`_1` 只有 1 位**照样认不出**——照抄建议等于没修。正确做法是回到约束本身（正则/接口契约）反推可行解（本次改为「秒数 +1 重算 HHMMSS」，保住单段 6 位数字才全兼容）。**结论：报告里的"建议改法"要当假设验证，不能当指令执行。**
- **覆盖/推送前先验证目标有没有别人未提交的改动（2026-09-23 实证）**：本地镜像只是快照，服务器可能**正被另一个会话改着**。把「比 md5」放在**推送前**而不是推后：本次因此在动手前一步发现服务器 `server.js` 与本地基线不一致，追查出一笔正在进行的流式链路重构（工作区 6 文件未提交），**当场停手**——既没覆盖对方数小时的工作，也没因「重启」把对方半成品带上线。**结论：发现不一致就停手查清 + 如实报告，不要用"我的是最新的"假设硬推；连"重启服务"也要先问（重启＝用服务器当前文件启动＝激活对方未完成的改动）。**
- **预检发现 md5 不一致时，绝不能和 scp 写在同一条 `&&` 链里继续推（2026-09-26 实证）**：同一条命令里「md5 预检 && scp」会让预检结果被打出来但**拦不住推送**——本次预检已显示服务器 chat.html 变成陌生 md5（`fa5dc29`，另一会话的 PWA 未提交改动），`&&` 链照样执行了覆盖，靠对方留下的 `.bak` 才救回。正确做法：**预检单独跑、人工核对通过后再单独跑推送**；预检值 ≠ 本地上次推送值就停手。另：并行会话改动可从它的 `cp` 备份（文件名带时间戳）diff 恢复——恢复方式 = 以对方备份为底、把「我方最后一次同步之后的增量」重新叠上去，而不是反过来。
- **前端 CSS/死代码清理的两个解析盲区，删前必须先查（2026-09-26 chat.html 双重实证）**：①**动态拼接类名**——`className="msg ev-"+kind`、`classList.add("hd-"+layout)` 生成的类（ev-diary/hd-wx/hd-sms）完整串在源码里从未出现，任何「完整串零命中→判死」的静态检测必误删；删类前必须先 grep `className="..."+`、`classList.add("..."+`、`class="...${` 拼接模式，把拼接前缀对应的所有可能类排除。②**跨行注释**——注释首行含类名+`{`（如「原 `.x{display:none}` 已删」的历史注解）会被规则块扫描器当选择器行，花括号在注释内自配对→**只删首行、留下半截注释**，孤儿 `*/` 破坏 CSS 解析吞掉后面的活规则（本次吞掉 claude 布局 `.rw{background:transparent!important}`，极简思考胶囊错误出现灰底）；清理脚本的块扫描必须先整体跳过 `/*...*/` 区间。**且清理后的实测必须对照预期视觉行为，「元素存在且有值」≠正确**（本次实测看到 #f5f5f5 背景一度误判正常）。
- **自研解析器判死活必须配保守池+人工复核，别信单一提取器（2026-09-30 D3-1 实证）**：写审计扫描器提「活类名全集」时用自写引号状态机提取 JS 字符串字面量，被正则字面量里的引号（`/['"]/` 类）错位污染——错位点之后全部漏收，46 种"死类"里 42 种是冤案（ctx-lamp/alert-item/tt-h 明明在 innerHTML 拼接里）。改「掩掉 style 区间后全文件 token 池」（不看引号结构，超保守宁漏杀不错杀）后收敛到 4 种真死类，再逐条 grep 复核+追变量值域才动手。**任何「零引用判死」的结论，提取器本身先要被证伪过一遍**；另注意删改清单跨基线重放（如并行会话 reset 后）必须对新基线重跑残留 grep——基版特有的引用（本次暖白版 L8917 wx 衬线条）不在旧清单里。
- **接口死活判定的调用面必须枚举全部封装形态（2026-09-26 大清洁第一批误删实证）**：`/admin/logs/pinned` 组与 `/admin/cross-window-inject` 被误删——chat.html 后台卡用 `admGet/admFetch(BASE+'/...')` 第三种封装调用，而调用面枚举只查了 `fetch(` 字面量与 `ADMIN_API+'...'` 拼接两种。**完整形态清单**：①`fetch(`/`EventSource(` 字面量 ②`ADMIN_API+'...'`/`BASE+'...'` 拼接 ③项目自封装函数（admGet/admFetch/apiRequest/admPost 等——先 grep 函数定义再收集其全部调用实参）④隐式全局（HTML id 直接裸用，不经 getElementById）。**审计方法用「全集差集」而不用逐行 diff**：提取删除前后两版的函数定义/路由路径/DOM id/顶层 const 全集做 comm 差集——diff 会把并行会话的「修改」（如 saveWakeSchedule 加 keep 参数）显示成删+加，逐行看误判为删除；差集只会列出真消失的符号。**回滚验证**：`git show <删除提交>^:file` 提取原文段+断言首尾行内容后插回。
- **记录推送前必须重拉核对 md5，编辑窗口内的并行写入会话会被无声覆盖（2026-10-01 1001-12/13 覆盖事故实证）**：取号时核对过「当天最大号」（规范只要求写前核对）不够——**推送前**还要重拉一次核对 md5，不一致就停手合并。本次「拉取→编辑→推送」窗口约 15 分钟，并行会话在窗口内写完并提交了 1001-12/1001-13 两条记录（已进 git 历史 d9cd7ce/9d3691d），我用旧底 tar 覆盖把两条吞掉并随我的提交固化；靠 git 历史恢复+撞号让位（对方号被引用故保留，我的改号）。同一晚 chat.html 推送因**预检与 scp 分链**拦下一次同类覆盖——此规矩对记录文件同等适用。另：撞号让位规则=「已被其他条目引用的号保留，未引用方改号」。
- **快照门槛是设计错误的第一道闸，"零差异"目标下死活判定必须逐属性实证（2026-10-01 主题变量化批1/2 双实证）**：批1 两处设计错误（claude 结构规则搬进布局层使 dark 意外获得从未有过的样式；跨行组选择器删半边致悬空选择器吞下一条规则）与批2 一处误删（同规则内 box-shadow/transition 活而其余死）全部由 computed style 快照抓住而非人工审查——**手算级联特异性会漏（body:has() 特异性含参数内 #chat 的 id），"零差异"类施工必须先跑基线快照再动手，差异清单逐条归因后才准过闸**。

##用户偏好层（约定、要求、反复强调的流程、用户厌恶的行为、产品理念等）
q1·所有的文案、提示词、显示出来的名称或者直接进入上下文的、聊天ai能直接获取到的信息，都要询问用户意见。现给出你的打算，然后用户修改或者直接用。
q2·当用户给出明确指令，做任务（除只读）前，审查实际相关代码以后，与用户确认的格式流：我理解的需求+我参考了哪些项目（如果有）+预计修改的文件+相关的功能+改完有什么实际效果+风险（如果有）+是否会引入新问题+任务思路（有哪些实现 方法，我的决策建议）。
q3·当用户给出需求模糊的指令，调查实际相关代码以后，与用户确认的格式流：我理解的需求，是否对？然后给出多个选项来逐级确认。确认清楚以后再执行q2。
q4.当用户说“总结会话”，你需要用代码块输出一份跨会话可继续执行任务的提示词。
q5.在任务过程中发现一些其他的业务逻辑有问题，或者代码质量低，或者高风险的点，以及死代码、错误注释，先记下来，任务结束以后汇报。
q6.任何涉及代码、配置、数据结构、接口、状态、提示词、业务逻辑或功能行为的修改，不得只检查被直接修改的文件。执行修改前，先识别该功能的上下游依赖、调用关系、共享状态、重复实现以及可能受影响的其他入口；修改后再次检查相关影响面，并进行必要的代码检查、测试、实际运行验证和 diff 审查。任务完成的标准不是“目标文件已经修改”，而是“本次需求对应的完整功能链路已经验证，且没有因为本次修改产生已知的上下游不一致或新的逻辑问题”。

## 单任务收尾流程（看任务大小。值得记的才记。如很小的只读任务就不需要记录）

1. **不新建独立文件**：直接打开**服务器上**当天的 `/opt/dylan-heartbeat/agent每日工作记录/工作记录_YYYY-MM-DD.md`（没有就新建），在**开头**（标题之后、旧内容之前）**插入**会话总结；**最新在上、倒序排列**（越新越靠前）。**每条会话总结的标题必须带当日序号 id `MMDD-NN`**（如 `0904-01`、`0904-02`……`NN` 为该记录在当天的第几次写入，从 `01` 起递增；当天现有条数+1 即新 id，写前重读当天文件核对防与并行会话撞号）。插入格式如下（按实际写）：
   ```markdown
   ## <MMDD-NN>
   > 时间：<时段>（可以获取服务器时间）。承接：<上一主题 / 若无>。
   ### 1. 干了什么（一句话概括）
   ### 2. 改动清单（文件 · 改了什么 · 是否已推送/生效）
   ### 3. 关键决策与理由、代码逻辑。
   ### 4. 验证结果
   ```

2. **总结后清理检查清单**（按顺序逐项核对）：
   - **失败经验**：ai跨项目通用行为决策层记到01，ai使用工具等执行层失败经验记到02，项目独有易踩坑节点项目层记到05任务索引。
   - **遗留事项**：删除已完成的事项。
   - **目录索引**：任务id+任务标题（十五字以内）+git编号+踩坑（踩坑包括原因+避坑指南），整体一条不超过80字。
   - **清理临时文件**：无用脚本、备份文件。
   - **系统变更**：`03_系统介绍.md`（静态路径/端口/路由/目录结构）同步更新（如有）。

3. **每日记录只存服务器**（2026-09-28 用户拍板，原「本地写+23:00 定时同步」机制废止）：工作记录只存在服务器 `agent每日工作记录/`，本地记录文件夹已删除；写完即推（单文件 `scp -O` + `md5sum` 复核，中文文件名走 tar 打包）。
