记忆蒸馏 · 定时设置i▾
每天在设定时间把「涵的日记」分批喂给模型抽取记忆候选，产出全部进待审队列等你裁决，不会直接入库。开关关掉就不自动跑；「立即跑一次」不受开关约束，随时可以手动跑。保存后写入 data/memory_distill_config.json，立即生效。
两块总结 · 定时设置i▾
每次对话开头那两块：Core Identity（写「规矩」，取材记忆池全部活跃 rule 条目）与 Long-term Understanding（写「理解」，取材全部活跃 fact 条目）——不是置顶那几条。每晚到点检查一次：记忆池没变化就完全不动（比对指纹，不调模型），变了才重新生成并写缓存。模型挂了沿用上一版，连上一版都没有才回退直注原始条目。开「增量生成」时，变化不多就只把「上一版 + 新增/改动/移除」喂给模型；关掉则每次全量重生成。
老数据重跑 · 逐批整理i▾
把记忆池里已有的活跃记忆一批一批过一遍，让模型判断该怎么整理：润色改写 / 补充信息 / 合并碎片 / 补抽漏掉的 / 建议沉底。**产出一律进待审**，不会自己动池子。每条都会先回原文取证，原文对不上的一律不动。「建议沉底」是删除级动作，不进待审，单独列出来等你定夺。
压缩参数配置i▾
生效范围提醒：「保留最近 / 消息少于 N 条 / 摘要字数 / 分块间隔」作用于「整段对话的自动压缩计划」；「自动分块目标 / 最少 / 最多条数」同时作用于「整段对话自动压缩计划」和「未覆盖区·自动分块」。请保持：摘要最少 ≤ 摘要最多；块最少 ≤ 目标 ≤ 块最多。

记忆流水线·判定提示词i▾
新记忆入库前，流水线用它调用 LLM 判定「候选 × 已有记忆」的关系（duplicate=重复 / update=更新 / coexist=共存 / need_review=待审）并决定去向：重复拒收、更新与待审进人工队列、共存直接入库。占位符 ${existing_kind} ${existing_text} ${candidate_kind} ${candidate_text} 运行时自动填充。可直接修改保存覆盖内置；「恢复内置默认」清空自定义。
记忆蒸馏·抽取提示词i▾
后台蒸馏每批把「若干篇日记 + 按日期检索到的当天对话原文」打包喂给模型，用它抽取值得长期记住的候选——产出全部进记忆待审队列，不直接入池。占位符 ${DIARY_COUNT} 运行时替换为本次日记篇数；「上一批已提取的记忆」与「=== 材料 ===」由运行时自动拼在 User 提示词之后，不需要自己写。两边都留空即用内置默认；点「恢复内置默认」清空自定义。

两块总结·合并提示词（1003-15）i▾
一次 LLM 调用同时生成两块（Core Identity + Long-term Understanding），模型根据全部材料自己分配，两块不重复。占位符（运行时自动填充）：${RULE_COUNT} 规则类条数、${RULE_PREVIOUS_BLOCK} 上一版、${RULE_DELTA_BLOCK} 增量、${RULE_MEMORY_LIST} 规则类清单，${FACT_*} 同义为事实类。全量模式两块材料都喂；增量模式只喂「上一版 + 增量记忆」，模型可调用关键词检索工具补充材料（最多 4 轮）。两边都留空即用内置默认；点「恢复内置默认」清空自定义。
System 提示词（一次生成两块的角色与规则、块标记【CORE_IDENTITY】【UNDERSTANDING】）
User 提示词（两块材料分节，可用占位符 ${RULE_*} ${FACT_*}）
